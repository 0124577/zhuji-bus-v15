# 诸暨公交 · 长者易用版（v1.5.0）

面向老年用户的诸暨公交查询应用：大字号、少层级、点两下就能看到「还有几站」。
原生 HTML / CSS / JS 单页应用，无框架、无打包器；同一套代码通过 GitHub Pages 提供网页版，通过 Capacitor 打包成安卓 APK。

- 网页版：<https://0124577.github.io/zhuji-bus-navi/>
- 源码仓库：<https://github.com/0124577/zhuji-bus-navi>
- 安卓安装包：见仓库 Releases 中的 `zhuji-bus-navi-v1.5.0.apk`

## 一、这一版做了什么

### 1. 站点线路数据：版本同步 + 降级自愈

| 能力 | 实现 |
|---|---|
| 版本号增量同步 | `data/manifest.json` 记录数据版本、总分片哈希；启动后与本地版本比对，只下载哈希变化的分片 |
| 每 2 天全量校准 | 逐个重算本地分片哈希，与官方清单比对；不一致的分片自动重下修复，并记录校准时间 |
| 官方接口不可用 | 自动使用本地最后一份有效快照（本地缓存或内置基线），功能不中断 |
| 实时车辆接口失效 | 关闭「到站预估」字段，只展示时刻表 / 首末班，不再给「还有几站、约几分钟」 |
| 数据过期提示 | 仅在界面上给一行静态文字（设置页 + 出行页脚注），**不弹窗、不通知、不置红点** |
| 更新联动 | 数据版本变化后自动重建索引并重新规划，首末班 / 收班校验立即按新数据生效 |

数据同步全程静默：没有公告、没有「发现新版本」提示、没有小红点。

### 2. AI 出行助手（助手 Tab）

- 自然语言输入：「我在火车站，想去草塔停车场」「1路首末班几点」
- 识别起终点、出行偏好（最快 / 少换乘 / 少走路）
- 调用现有路线规划引擎，返回**文字总结 + 可点击方案卡片**，点卡片直接进入换乘详情页
- 支持查询线路首末班、收班状态与最近班次
- 完全本地解析，断网也能用；不发送任何系统推送

> 说明：当前版本不依赖云端大模型（无模型密钥场景也能交付）。意图解析用本地词表 + 站点长名优先匹配，结果确定、可测试、离线可用；如果后续要接大模型，只需替换 `www/js/ai.js` 的 `parse()` 一处。

### 3. 出行链路简化

```
出行页（精简方案列表） → 换乘详情页（整合全部信息） → 独立线路页（次要入口）
```

- **方案列表卡**只保留四项：总时长、步行距离、公交线路、车辆实时状态；点卡片进详情
- **换乘详情页**：直达方案展示整条线路实时车辆与全部途经站点；换乘方案按段展示实时到站与途经站点
- **就地改站**：点详情页的「上车站 / 下车站」唤起站点弹窗，改完立即重算，不跳独立线路页
- **独立线路页**改为次要入口，需主动点「查看完整线路（含全部车辆）」才进入
- 列表页不再展开分段、不再跳线路页

## 二、功能清单

- **首页**：线路号搜索、收藏线路 / 站点、到站提醒概览、全部线路列表
- **出行**：起终点选择（线路展开 / 站名搜索 / 我的位置）、多套方案列表、直达优先、近距离步行提示
- **换乘详情**：到目的地剩余站数大字条、分段实时车辆、横向站点条、竖向大字时间轴、站点铃铛提醒、就地改上下车点
- **线路页**：实时车辆位置、剩余站与预计到站、竖向大字时间轴、发车时刻表、上下行切换、收藏
- **站点页**：途经线路、实时车辆、到站时间、收藏
- **设置**：4 套主题色、提示音 / 震动 / 音量、通知权限状态与引导、提醒轮询间隔、数据版本与校准、清除缓存、关于
- **边界场景**：定位失败、搜索无结果、网络异常、实时接口失效、无直达线路、收班 / 首班前、数据过期

## 三、网页部署

纯静态资源，任意静态服务器即可。

```bash
# 本地预览
python -m http.server 8899 --directory www
# 打开 http://127.0.0.1:8899/index.html
```

GitHub Pages：

```bash
git subtree push --prefix www origin gh-pages
# 仓库 Settings → Pages → Branch 选 gh-pages / root
```

地址形如 `https://<用户名>.github.io/<仓库名>/`。

## 四、安卓打包（Capacitor）

环境：JDK 17、Android SDK（platform 34 / build-tools 34.0.0）、Gradle 8.2.1。

```bash
npm install
npx cap sync android
cd android
JAVA_HOME=/path/to/jdk-17 ./gradlew assembleRelease
# 产物：android/app/build/outputs/apk/release/app-release.apk
```

版本号在 `android/app/build.gradle`（`versionCode` / `versionName`）与 `www/js/core.js` 的 `CFG.VERSION` 同步修改。
应用含自写原生插件 `ZjNotify`（通知渠道、响铃 / 震动、跳系统设置），Android 13+ 需 `POST_NOTIFICATIONS` 权限。

## 五、数据说明

### 静态数据（本地）

- 来源：诸暨公交官方站点表快照，生成于 2026-11-18
- 规模：395 条线路 / 779 个方向 / 22,186 个站点位置 / 3,061 个不重复站名
- 内置基线：`www/data/snapshot.js`（首启与离线可用）
- 同步产物：`www/data/manifest.json` + `www/data/ds/c00–c07.json`（每片 50 条线路，站名内联）
- 版本号：`2026111901`；清单含每片 FNV-1a 哈希与整体哈希，用于增量比对与自愈校验
- 重新生成：`node scripts/build-dataset.mjs [版本号]`

### 实时接口（预留）

- 官方地址：`https://zjcx.zhuji.gov.cn:9443`
- 线路详情、发车时刻表、实时车辆（POST JSON，无需登录）
- 口径：`vehicleOrder` 为已驶离站（1 基），剩余站 = 目标站序号 − `vehicleOrder`
- 接口连续失败 2 次即判定实时能力降级，界面自动切换为时刻表 / 静态口径

### 首末班与收班口径

- 收班判定以「末班车到达**你这一站**」为界：末班时间 + 起点到本站的静态行驶时间
- 末班已发但尚未驶过本站时，仍显示剩余站数并标注「末班车已发出」
- 首班前 15 分钟以上判为「首班未发」
- 收班 / 首班前一律不渲染剩余站数与到达时间

### 数据同步口径

- 启动 1.5 秒后检查版本，之后每 6 小时一次
- 全量校准：启动后 4 秒一次，之后每 12 小时检查，满 2 天执行一次
- 同步失败只影响「是否最新」，不影响使用；界面保留本地最后有效快照

## 八、已知限制

1. 无地图渲染，换乘耗时、站间距离、步行距离均为静态里程 / 直线距离估算
2. 收班时间来自静态快照，官方改点后需重新生成快照（或用同步机制下发新版本）
3. 发车时刻表接口部分线路返回空或 500，此时只显示首末班，不影响实时车辆
4. 系统通知需 Android 13+ 授予 `POST_NOTIFICATIONS`
5. 到站提醒依赖实时接口，接口中断时提醒暂停，不会发系统推送兜底
