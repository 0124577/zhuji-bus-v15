## 三、关键场景说明

### 3.1 「到目的地还有 N 站」是页面主角

- **出行结果卡**：第一行 `到目的地还有 19 站`（数字 22px 粉色）+ 右侧「直达 / 换乘 1 次」标签；第二行 `约 42 分钟 · 23:48 到达 · 8.6 公里`；再往下才是分段信息与「看实时车辆与到站提醒」。
- **方案详情页**：顶部渐变大字条永远是「到目的地还有 N 站」（35px），右栏给「约 X 分钟 · HH:MM 到达」，第二行给当前最近一辆车「50路 还有 3 站到上车站」；没有在线车辆时第二行换成「暂无在线车辆 · 按静态里程估算」，**数字不会消失**——这是 v1.1.0 只在有车时才显示高亮条的修正。
- 口径：`N` = 各乘车段站数之和（换乘方案累计），与「乘车 19 站」完全一致，不会出现两处数字不一致。

### 3.5 到站提醒：响铃 + 震动 + 系统通知

- 触发链：`Reminder.fire()` → `ZJ.Sound.chime()` → `ZJ.UI.vibrate([400,150,400,150,700])` → `ZJ.Notify.fire(title, body)` → 应用内弹层。
- 网页环境没有 `Capacitor.Plugins.ZjNotify`，`Notify.status()` 返回 `unsupported`，页面明确写「当前环境不支持系统通知，到站时只在 App 内弹窗提示」，不做假开关。
- APK 内：Android 13+ 申请 `POST_NOTIFICATIONS`；通知通道按「声音 / 震动」四种组合分别创建；`notify()` 在无权限时返回 `{shown:false, reason:'no-permission'}`，前端据此不显示"已发送"。
- 提醒依赖实时接口，接口中断时状态显示「数据中断 / 暂停」，不会误报。

### 3.6 边界与降级

| 场景 | 表现 |
|---|---|
| 实时接口连续 2 次失败 | `ZJ.Api.degraded = true`；线路页顶部 `#lineBanner`、详情页顶部 `.degrade-banner` 显示「实时数据已自动降级为静态数据」+ 重试；静态站序、首末班、收藏、换乘、提醒照常可用 |
| 网络异常（全部接口抛错） | 数据卡「实时车辆暂不可用」+ 原因 + 重新获取；页脚注明「当前显示静态站点数据」 |
| 无直达线路 | 给出 1 次换乘方案，必要时 2 次换乘；确实没有则空态提示「没有直达或换乘线路，可以换一个邻近站点试试」 |
| 站点搜索无结果 | 弹层显示「没有找到包含「…」的站点，换一个关键词试试」 |
| 定位被拒绝 | 首页正常渲染，`ZJ.Geo.state === 'fail'`，「我的位置」提示不可用，无横向溢出 |
| 收班时段 | 数据卡「已收班 · 末班 17:50 已发出 · 明日首班 06:20」，**不再显示剩余站数与到达时间**；字号与布局不变，仅内容切换（v1.4.0 修正） |
| 实时预估失效 | 关闭「还有 N 站 / 约 M 分钟」，改展示起点发车时刻表；时刻表也没有时退到首末班（v1.5.0） |
| 站点线路数据过期 / 官方不可用 | 用本地最后有效快照继续跑，界面只多一行灰色小字「数据为 X 天前版本」；**无弹窗 / 红点 / 公告**（v1.5.0） |
| 安卓返回键 | 优先关闭详情页 / 弹层，返回后仍停留在原 Tab |

### 3.7 首末班时间校验（v1.4.0 Bug 修复）

**问题**：v1.3.0 只在「没有在线车辆」时才提收班，一旦接口返回了过期车辆或走静态估算，夜间仍会给出「还有 6 站 · 约 18 分钟」与「00:17 到达」，属于明显错误信息。

**修复**：新增 `ZJ.Service`（`www/js/core.js`），以「末班车到达**你这一站**的时刻」为界，任何一次渲染 / 刷新都重新判定，不缓存。

| 状态 | 判定条件 | 界面 |
|---|---|---|
| `running` | 首班已发 且 未过末班 | 剩余站数 + 到达时间（与原来一致） |
| `lastGone` | 末班已从起点发出，但尚未驶过本站 | 照常显示，另加「末班车已发出」标签 |
| `closed` | 当前时间 > 末班 + 起点→本站行驶时间 | 「已收班」+ 末班时间 + 明日首班，**无站数、无到达时间** |
| `before` | 当前时间 < 首班 − 15 分钟 | 「首班未发」+ 今日首班，**无站数、无到达时间** |
| `unknown` | 该方向无首末班数据 | 维持旧逻辑（不拦截） |

生效位置与刷新时机：

- 出行页方案卡（含收班过滤与排序）、方案详情大字条 / 分段实时块 / 竖向时间轴、线路页数据卡与运营状态标签、站点页每条线路、提醒引擎与首页提醒卡片
- 详情页 20 秒轮询、提醒引擎按设置间隔、出行页每 30 秒比对状态；跨过末班时间自动切换，不需重新查询
- 收班时详情页跳过接口请求，只做重绘，减少无效流量

### 3.9 数据同步 + 降级自愈（v1.5.0）

| 项 | 实现 |
|---|---|
| 清单 | `www/data/manifest.json`：`version / format / algorithm / counts{lines,dirs,stops,names} / totalHash / chunks[]` |
| 分片 | `www/data/ds/c00–c07.json`，每片 50 条线路（站名内联），片内 `hash` 与清单一致 |
| 算法 | FNV-1a 32 位（`fnv1a`，与 `scripts/build-dataset.mjs` 同一实现） |
| 缓存 | `localStorage: zjbus.ds.v1`，`validCache()` 校验 version / 分片哈希 / 整体哈希自洽才启用 |
| 增量检查 | 启动 1.5 秒后一次，此后每 6 小时；只下 `hash` 变化的片 |
| 全量校准 | 启动 4 秒后一次，此后每 12 小时检查，**距上次满 2 天**（`CALIBRATE_INTERVAL`）执行一次 |
| 自愈策略 | ① 分片哈希不符 → 只重下该片；② 整体 `totalHash` 或条数不符 → 全量重取一次；③ 官方版本低于本地 → 以官方为准清缓存 |
| 官方不可用 | 用本地最后有效快照继续跑；无本地缓存时用内置基线（打包在 `snapshot.js` 里的那 395 条） |
| 过期提示 | `ageDays > 30` 或 `lastCheck > 7 天` → `state='stale'`，页面只多一行灰色小字 |
| 静默 | **无弹窗、无红点、无公告、无变更通知**（代码中 `datasync.js` 不引用 `ZJ.Notify`） |
| 联动 | 落地即 `ZJ.Data.rebuild()` + 广播 listeners → 首末班/收班校验、出行方案、详情页、线路页、站点页、首页、设置页全部用新数据重算 |

**实时失效降级**：`ZJ.Api.liveOff = mode==='static' || health.degraded` 一旦为真，

- 线路页 / 站点页 / 详情页 / 竖向时间轴**不再输出**「还有 N 站」「约 M 分钟」「HH:MM 到站」
- 改为「实时车辆不可用，已关闭到站预估 · 时刻表 07:20 / 07:50 / …」，时刻表来自 `ZJ.Timetable`（30 分钟缓存，按首站行驶时间过滤已发班次）
- 大字条右侧换成「全程约 N 分钟 · 按时刻表」，副文「实时不可用 · 已关闭到站预估 · 按时刻表」
- 时刻表也拿不到时退到「时刻表暂不可用 · 首班 06:20 / 末班 17:50」，不写「获取中」这种悬空文案

## 七、遗留与说明

1. 官方实时接口夜间收班后返回空车辆列表，属数据真实状态，页面按首末班判定显示「已收班」，不使用假数据填充。
2. 收班判定按「末班车到达上车站」而非「末班发车时间」：末班车已发出但尚未驶过本站时，仍显示剩余站数并标注「末班车已发出」，以免把还能坐到的车挡在外面。
3. 系统通知需 Android 13+ 授予 `POST_NOTIFICATIONS`；未授予时仍可弹窗 + 响铃 + 震动（App 在前台）。
4. 提醒轮询默认 15 秒、最短 10 秒；官方接口对高频请求有压力，未提供 5 秒以下档位。
5. 无地图渲染，换乘耗时、站间距离与步行提示均为静态里程 / 直线距离估算，并非路况实时耗时。
6. 静态快照需随官方线路调整重新生成（`scripts/extract-data.py` 依赖 v2.0.0 基线 `index.html`）。
7. 部分线路官方时刻表接口返回空数组，此时仅展示首末班与实时车辆。
8. 首末班时间同样来自静态快照，官方改点后需重新生成快照，否则收班判定会提前或延后。v1.5.0 起同步完成后会立即重建索引并重算收班判定，不需要重启 App。
9. 本版出行页回到 v1.1.0 的「线路展开 / 站名搜索」两 Tab 选站方式；v1.2.0 的「站名直查 + 三分区结果」实现保留在 `wip/single-list` 分支，需要时可切回。
10. AI 助手为**本地确定性语义解析**，不联网、不需要任何模型密钥：能认「从 A 到 B」「N 路 末班几点」「最快 / 少换乘 / 少走路」以及 3061 个站名的直接提及；不支持的开放式问句会给引导语而不是编答案。接大模型只需替换 `www/js/ai.js` 的 `parse()`。
11. 数据同步的分片是「每片 50 条线路」，与线路总数解耦：线路增减时只影响末片与 `counts.dirs/stops`，不必改分片数量。分片文件合计约 881 KB，首次启动仍需下载，之后按版本增量。
12. `scripts/verify-live.mjs` 会过滤官方 `getBusLinePlanSimpleTime` 的 HTTP 500（该接口对部分线路长期返回 500，属官方侧问题，`ZJ.Api.plan` 已改为不参与健康度统计，避免把整体拖入降级）。
